# W1 foreground service audit

## Findings

- The TV module targets API 34 and declares both `FOREGROUND_SERVICE` and `FOREGROUND_SERVICE_SPECIAL_USE`.
- `TvEqualizerService` is declared with `foregroundServiceType="specialUse"` and the required `android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE` property. The subtype is `audio_equalizer_control`.
- The merged debug manifest retains both permissions, the service type, and the subtype property. Evidence: `android/tv/build/intermediates/merged_manifests/debug/processDebugManifest/AndroidManifest.xml`, generated by `:tv:processDebugMainManifest`.
- `onCreate()` creates the notification channel and builds the foreground notification before calling `startForeground`. Promotion occurs before the command dispatcher and engine thread are initialized, so the service promotes promptly.
- `FgsPolicy.typeForSdk()` supplies type `0` below API 34, including API 31, and uses `ServiceInfo.FOREGROUND_SERVICE_TYPE_SPECIAL_USE` at API 34 and above. `TvEqualizerService` uses this helper for the platform call; the API 34 constant is evaluated only inside the guarded branch.
- The API 31 path is the three-argument `startForeground` overload with type `0`; API 31 supports that overload and does not require a matching special-use type.

## Verification

Added `FgsPolicyTest` coverage for API 31, API 33, API 34, API 35, and API 36. These tests exercise the helper used by the service and compare API 34+ against the platform constant. `TvForegroundServiceManifestTest` parses the actual source manifest with a namespace-aware DOM parser and checks both permissions, the service type, and subtype property. The source manifest is registered as a unit test input so edits invalidate the test task.

Command, from `android/` with the configured JDK 17 and Android SDK:

```text
./gradlew :tv:testDebugUnitTest :tv:lint :tv:processDebugMainManifest
BUILD SUCCESSFUL in 8s (32 actionable tasks: 9 executed, 23 up-to-date)
```

The unit test XML reports 59 passing tests total: 5 policy tests and 1 manifest binding test, plus the existing TV suite.

## Limits

No device, emulator, or runtime checks were performed. Existing API 31 device evidence is external to this audit; API 34 runtime behavior remains unverified. The merged manifest and JVM policy tests establish build-time declaration and branch selection, not platform acceptance at runtime.
